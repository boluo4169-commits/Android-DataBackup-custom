# DataBackup Companion v2.0 深挖：诊断包 + 设置界面

> 目的：站在「用户报告问题 → 把诊断包发来 → 我要据此定位」的视角，系统性盘点还能增强什么。
> 依据均为源码事实（已标注文件 + 行号）；标注【建议】的是判断，不是现状。
> 对照样本：手机端 App 的日志体系（`source/core/util/src/main/kotlin/com/xayah/core/util/LogUtil.kt`）。

---

## 0. 结论先行

| 优先级 | 缺口 | 影响 |
|---|---|---|
| **P0** | **PC 端日志完全不落盘**（只留在界面文本框里，进程退出即消失；无头模式走 stdout） | 诊断包里**没有任何日志**，判断"登录失败/传输出错"只能靠用户口述 —— 今天 Z 的案例就卡在这 |
| **P0** | 诊断包看不出「占着 2121 的是不是我们自己的服务」 | 无法区分"密码错" vs "别的 FTP 软件占了端口" |
| **P1** | 防火墙只打印 profile 状态，不查规则是否存在、有没有程序级 Block 规则 | 2026-09-17 实测：`C:\Program Files\Python314\python.exe` 有一条 Public 的 **Block** 规则，用它起的服务收不到任何连接，诊断包完全看不出来 |
| **P1** | 网络信息只有 IP 列表，没有子网掩码/网关/网卡类型 | 用户不知道该填哪个（Z 的包里两个 IP：`10.45.142.243`、`26.136.71.229`） |
| **P1** | 配置快照缺：密码是否为空、**日志无时间戳**、是否管理员 | 登录失败第一条要核的就是这些 |
| **P2** | 界面细节：日志区不能清空/保存/复制、顶栏不显示在线客户端数、诊断完成不提示路径 | 体验与自助排查成本 |

## 1. 诊断包现状（事实）

`create_diagnose_zip()` — `companion/ftp-server/src/ftp_core.py:761` 产出 5 个文件：

| 文件 | 采集函数 | 内容 | 缺口 |
|---|---|---|---|
| `environment.txt` | `collect_environment()` :553 | 系统/Python/主机名/局域网 IP/备份目录/磁盘空间/端口状态/被动段/防火墙 profile | 无网关、无掩码、无网卡类型、**无防火墙规则明细、无管理员状态、无工具版本/运行方式** |
| `ftp_status.txt` | `collect_ftp_status()` :584 | 用户名（密码有意不输出）、端口、端口状态、自检说明 | **无密码是否为空、无服务是否运行、无最近会话记录** |
| `file_inventory.txt` | `collect_file_inventory()` :630 | 备份目录树、0 字节文件 | 尚可；建议加"最近修改时间"与"按包汇总" |
| `integrity_check.txt` | `collect_integrity()` :667 | md5 配对、config json 合法性、异常汇总 | 尚可；建议加"归档体积 vs 记录的原始大小"对账提示 |
| `diagnose.json` | `collect_summary_json()` :745 | 时间/平台/备份目录/局域网 IP/端口/异常 | 本轮已加 `port_owner`、`service_running`（未提交）；建议再加版本/日志路径 |

## 2. 对标手机端（它为什么好用）

`LogUtil.kt` 的设计可以照搬：

| 能力 | App 端做法 | PC 端现状 |
|---|---|---|
| 日志落盘 | `log_<yyyyMMdd_HHmmss>.txt` 滚动保留 **10 个**（`MAX_LOG_FILES` :30） | **无** |
| 环境 header | Version / Model / ABIs / SDK / Namespace / **SU** / `$PATH` / `$HOME`（`logHeader()` :66-78） | 有（诊断包 environment.txt），但**不在日志里** |
| 日志 tag | `Common` / `SHELL_IN` / `SHELL_OUT` / `SHELL_CODE` | 无 tag（只有纯文本行） |
| 一键打包 | `createLogsZip()` :189 → `logs_<ts>.zip`，含最近 10 个日志 + `system_evidence.txt` | 有（诊断包），但**不含日志** |
| 取证兜底 | 每类取证单独 `runCatching`，失败不影响导出（:150-185） | 有（每个探测 try/except）✓ |
| 崩溃取证 | 进程被杀时抓 dmesg/thermal/meminfo/logcat（`logKillEvidence()` :149） | 无对应能力（可选） |

**核心差距一句话**：App 端是「日志常驻磁盘 + 事件即写 + 一键打包」，PC 端是「日志只在内存里滚动 800 行（`DataBackupFTPServer.py:25` `LOG_MAX_LINES = 800`，`log()` :245 只写到 Text 控件）」。

## 3. 诊断包增强清单

### P0-1 日志落盘 + 打包【建议，难度：中】

- 新增落盘：`ftp_core` 加一个轻量 `FileLogger`（写 `log_<ts>.txt` 到固定目录，例如 `%TEMP%\DataBackupFTP\logs\`，**不要写进备份目录**），滚动保留 5 个
- 写入点：GUI 的 `log()`（:245）与 `FtpService.on_log` 同时落一份；无头模式（`out()` :57）也落
- 日志行格式带**时间戳 + tag**，例如 `12:31:05 [FTP] 通信正常: 账号 bbbfff 登录成功（来自 10.45.142.2）`
- 诊断包新增 `session_logs.txt`：合并最近 1 个日志文件的末尾 N 行（建议 300 行，超长截断并标注"已截断"）
- 脱敏：日志里只有用户名与 IP，**不写密码**（现状已满足）

### P0-2 端口 banner 自连探测【建议，难度：小】

- 新增 `probe_port_banner(port)`：连 `127.0.0.1:port`，读一行问候语（超时 2s）
- 输出：`端口 2121 的 FTP 问候语: DataBackup Companion FTP server ready.` + `是否本工具: 是`
- 价值：一眼判断占端口的是不是我们的服务；若问候语是别的软件 → 直接告诉用户换端口

### P0-3 配置快照【建议，难度：小】

新增到 `ftp_status.txt`：
- 用户名、**密码是否为空 + 长度**（永不输出内容）
- 端口、备份目录、主题
- 工具版本（`COMPANION_VERSION` :33）、构建 tag（`app_build_tag()` :52）
- 运行方式：`getattr(sys, "frozen", False)` → exe / bat / 源码

### P0-4 是否管理员【建议，难度：小】

`ctypes.windll.shell32.IsUserAnAdmin()`；非管理员时防火墙/规则相关探测都可能静默失败，包里要写清楚。

### P1-1 防火墙明细【建议，难度：中】

- 用 `netsh advfirewall firewall show rule name="DataBackup FTP 2121"` 与被动段规则，输出「存在/启用/协议/端口/远程 IP/配置文件」
- **程序级 Block 规则扫描**：`netsh advfirewall firewall show rule name=all dir=in` 里找 `Program:` 含 python 且 `Action: Block` 的规则 → 直接提示「检测到 python.exe 的 Block 规则，用 python.exe 起服务会被拦；bat/exe 走 pythonw.exe 不受影响」
- 性能：完整枚举规则约 1–3 秒，放进诊断可接受；务必 `timeout=15`

### P1-2 网络明细【建议，难度：中】

- 默认网关（`ipconfig` / `Get-NetRoute`）、子网掩码
- 网卡描述（`Get-NetAdapter`）：标注虚拟网卡（描述含 VMware/VirtualBox/TAP/Clash/Tun/Radmin）
- 输出形如：`10.45.142.243/24 网关 10.45.142.1 [真实网卡·手机填这个]`、`26.136.71.229 [虚拟网卡·不要填]`
- 已知脆弱点：`primary_lan_ip()`（:93）用 UDP connect `8.8.8.8` 推导出口 IP——**无外网时返回空**，此时"推荐"会退回 `getaddrinfo` 顺序（可能把虚拟网卡排第一）。【建议】在这种情况下改用默认网关所在网段的地址，并在包里标注"推荐地址可信度：低"

### P1-3 备份目录可写 + 磁盘阈值【建议，难度：小】

- 写 `__diag_write_test__` 再删除，验证可写/权限
- 剩余空间低于阈值（如 1 GiB 或 5%）时进异常列表

### P1-4 被动端口段抽查【建议，难度：小】

抽样 60000/60025/60050/60075/60100 是否被占（ftplib 传文件失败常见原因之一）。

### P1-5 包内附 `README.txt`【建议，难度：小】

写清：每个文件是干什么的、怎么配合手机端「导出日志」、常见失败怎么自查（降低来回沟通）。

### P2（可选）

- 日志里统计「最近连接过的客户端 IP + 次数」，直接回答"手机到底连没连上"
- 诊断包带一个 `最近失败原因` 字段（从日志里提取最后一条含「失败/错误」的行）
- 参考 App 的 `logKillEvidence`：服务异常退出时抓 Windows 事件日志（可选，收益一般）

## 4. 设置界面 / GUI 逐板块盘点

> 代码位置均指 `DataBackupFTPServer.py`；区块注释与行号见源码。

| 板块 | 现状 | 问题 / 缺口 | 建议 | 难度 |
|---|---|---|---|---|
| **顶部：状态 + 启停**（:136） | `● 服务运行中 / ● 未启动` + 开启/停止按钮；运行中禁用表单 | **在线客户端数没用上**（`FtpService.connections` 有值但不显示） | 状态后加「当前连接 N」；停止时提示"服务已停止，端口已释放" | 小 |
| **表单：账号/密码/端口/目录**（:149） | 用户名、密码（可随机/显示）、端口、目录（浏览+历史） | 端口被占用只提示"已被占用"；目录不存在时会尝试创建（用户未必知道） | 占用提示带**进程名**（现有 `describe_port()` 可直接复用）；目录不存在时明确提示"已为你创建 X" | 小 |
| **连接信息卡片**（:202 `refresh_card()`） | 推荐地址 + 备用地址 + 端口/账号/密码/远程目录/传输模式 + 复制全部 | 远程目录**写死 `/`**，而 App 账号里实际可能是 `pad`，用户容易填错 | 卡片把「远程路径」改成说明式：「以 App 账号里的远程路径为准（当前工具根目录为 X）」，或允许手动覆盖 | 小 |
| **运行日志**（:238） | 文本框滚动 800 行，自动滚到底 | **无时间戳**、**不能清空/保存/复制选中** | ①日志行加 `HH:MM:SS` 前缀（对定位最重要）②右键菜单：复制 / 清空 / 保存到文件 | 小 |
| **底部：诊断包 / 打开目录 / 项目主页 / 主题**（:258） | 生成诊断包（异步 :272）、打开备份目录、主页、深色模式开关 | 诊断生成后只打一行路径，**不可点/不自动打开所在文件夹** | 生成后提示「已生成：xxx（点此打开所在文件夹）」，或加一个"打开诊断包目录"按钮 | 小 |
| **诊断流程**（:272 `make_diagnose()`） | 线程里跑，日志区打"正在收集…" | 无进度/无失败原因细分（异常只打印 str(e)） | 分步骤打点（环境→端口→防火墙→网络→完整性），失败打印异常类型 | 小 |
| **主题**（:309 `apply_theme()`） | 浅/深两套配色，选择持久化 | — | 可考虑跟随系统（读注册表 `AppsUseLightTheme`），非必需 | 小 |
| **整体** | 关窗前保存配置（:489 `on_close()`） | 无托盘、无开机自启、无"最小化到托盘" | 按需（FTP 服务常驻场景有价值） | 中 |

## 5. 健壮性 / 代码层

**做得好的（保持）**
- 每个外部命令探测都 `timeout` + `try/except`（`collect_environment()` :553 起）
- 日志泵 100ms 轮询（`pump_log_queue()` :473），服务线程不直接碰控件
- 主题切换不影响运行中的服务
- 密码不进诊断包（`collect_ftp_status()` :584）

**脆弱点（建议处理）**

| 项 | 位置 | 风险 | 建议 |
|---|---|---|---|
| netstat 解析按列索引 | `port_owner()` :143 | 列数变化/其它语言系统会误判 | 已限制 Windows + 有兜底；建议再加"解析不到就留空"的显式提示 |
| `primary_lan_ip()` 依赖外网 | :93 | 无外网/代理环境可能推导失败 | 失败时改用默认网关同网段 IP，并降低"推荐"可信度 |
| 控制台 attach 编码 | `attach_parent_console()` :42 | 非控制台宿主（pythonw）时 stdout 为 None | 现有 `out()` :57 已判空 ✓ |
| 写入路径 | `create_diagnose_zip()` :761 | **默认写在备份目录**（易污染用户数据，我今天误踩） | 诊断包默认写到临时目录，或让用户/调用方显式指定；GUI 生成后再提示"已复制到桌面/下载"由用户选择 |
| 日志无落盘 | — | 崩溃/退出后无法回溯 | 见 P0-1 |

## 6. 建议实施顺序

| 批次 | 内容 | 预期收益 |
|---|---|---|
| **批次 1** | P0-1 日志落盘+打包、P0-2 banner 探测、P0-3 配置快照、P0-4 管理员状态 | 直接解决 Z 类"登录失败"定位：包里能看到日志、能判断占端口的是谁 |
| **批次 2** | P1-1 防火墙明细、P1-2 网络明细、P1-3 目录可写、P1-4 被动端口抽查、P1-5 README.txt | 覆盖"能连但传不了 / 能传但别处出问题 / 环境类"问题 |
| **批次 3** | 界面：日志时间戳+右键菜单、顶部在线数、占用提示带进程名、卡片远程目录说明、诊断完成提示路径 | 用户自助排查成本下降，少一轮来回 |

**约束**：不输出任何明文密码；所有外部命令探测超时 ≤15s；诊断包不写入备份目录（除非调用方显式指定）。
