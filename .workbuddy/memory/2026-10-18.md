# 2026-10-18 · v3.15.1 发布

## 起因

群友在 4.7 寸机器上开启「列表显示版本号」后，副标题 `包名 · 版本` 被单行省略截断，包名只剩
`info.m.age.appshare`、版本只剩 `5…`。用户判断为「DPI 自适应缺失」。

## 定位

不是 DPI 问题。`sp`/`dp` 本来就跟随系统缩放；真因是两项拼在同一行 + `maxLines=1`，窄屏只是让
「放不下」提前发生。

## 改法（`8a98811`）

- 版本移到标题行右侧：`LabelSmall` + `maxLines=1` + `TextOverflow.Clip`（不省略）
- 副标题只放包名，独占整行
- 应用名 `weight(1f, fill = false)` 让位：极窄屏优先保版本

## 验证

- 真机 `ZCYm7FY7`（3040×1904 @420dpi），系统字体 1.5 倍：名称+版本+包名全部完整，长版本
  `星野Scenec NJ 2026.10 Alpha14 (920261009)` 也不截断
- 回归：备份列表 / 详情页（版本号+版本码）/ 恢复列表 / 排序记忆 / 一次完整备份（6/6，完成页无残留提示）
- 影响面：`AppItem`、`listItems`、`ListScreen` 均只在 list 模块内部使用，无跨页复用

## 踩坑

1. **`wm size` / `wm density` 改完必须 `reset`**，否则设备停在非原生分辨率；`font_scale` 同理要还原 1.0。
2. **Git Bash 会把 `/sdcard/xxx` 当本地路径转换**（`uiautomator dump` 报 dumped 到 `E:/Dev/PortableGit/sdcard/`）→ 对 adb 的命令行路径参数加 `MSYS_NO_PATHCONV=1`。
3. **`adb exec-out screencap -p > 文件` 偶尔拿不到数据**，重试一次或先输出到 `/tmp` 再复制更稳。
4. **companion CI 修复验证成功**（`af35987`）：本次 `DataBackupFTPServer.exe` 自动产出（12,750,603 B），按惯例下载重命名为 `-v2.5.exe` 后替换无版本号资产。
